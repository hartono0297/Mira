Rencana pembangunan Mira

22 November 2026 · Proyek ChatCompany · Berdasarkan hasil brainstorming (brainstorming-chatcompany.pdf)

Mira dibangun bertahap. Setiap tahap menghasilkan aplikasi yang bisa dijalankan dan dicoba, jadi masalah ketahuan lebih awal dan urutan prioritas masih bisa diubah di tengah jalan.

Perkiraan waktu di dokumen ini kasar, dengan asumsi satu developer bekerja penuh waktu dan dibantu AI. Angka sebenarnya bisa bergeser setelah tahap 1 selesai, karena di situ bagian paling sulit (jaringan dan sinkronisasi) mulai terlihat.

Arsitektur teknis

Setiap laptop menjalankan aplikasi Mira yang sama. Tampilan dibuat dengan teknologi web, sedangkan semua urusan data, jaringan, dan keamanan ada di inti Rust.

Prinsip keamanan: semua enkripsi dan tanda tangan digital memakai pustaka yang sudah teruji luas, bukan buatan sendiri.

Tahapan pembangunan

Tahap 0. Fondasi

1 sampai 2 minggu
  • Repository Git dan proyek Tauri dengan React dan TypeScript.
  • Sistem token warna dengan tema Bata terang dan gelap, plus mode "Ikuti Windows".
  • Kerangka layar: sidebar, Chat, Board, Dokumen, dan Pengaturan, masih berisi data contoh.
  • Pembuatan kunci laptop dan layar pertama kali buka: isi nama, lalu buat tim baru atau gabung dengan kode.
  • Build otomatis yang menghasilkan installer Windows.

Selesai kalau: installer bisa dipasang di laptop kantor, aplikasi terbuka, nama tersimpan, dan mode terang serta gelap bekerja.

Tahap 1. Jaringan dan tim

2 sampai 3 minggu
  • Menemukan laptop rekan otomatis lewat mDNS, dengan cadangan input alamat manual dan QR code.
  • Koneksi terenkripsi antar laptop yang hanya menerima anggota tim.
  • Organisasi yang dibagi per tim, kode undangan dengan masa berlaku, serta peran Superadmin, Admin tim, Anggota, dan Tamu.
  • Alamat terakhir setiap rekan diingat, supaya tetap tersambung lewat VPN kantor.
  • Status koneksi: LAN kantor, VPN, atau tidak tersambung.
  • Panduan izin Windows Firewall di layar pertama.

Selesai kalau: tiga laptop di kantor saling melihat dalam daftar "Di jaringan", satu laptop lewat VPN ikut tersambung, dan laptop tanpa kode undangan ditolak.

Tahap 2. Chat dasar

2 sampai 3 minggu
  • Channel per proyek dan chat pribadi, dengan balas pesan dan mention.
  • Status pesan: Dibaca, Diterima laptopnya, Dititipkan.
  • Titipan pesan tersegel untuk rekan yang offline.
  • Kirim file kecil (di bawah sekitar 20 MB) yang disalin ke semua anggota.
  • Notifikasi Windows untuk pesan baru.

Selesai kalau: pesan ke rekan yang laptopnya mati sampai lewat titipan begitu laptopnya menyala, walaupun laptop pengirim sudah dimatikan.

Tahap 3. Board dasar

Versi pertama siap dipakai2 sampai 3 minggu
  • Board per proyek dengan kolom To do, Dikerjakan, Selesai, dan kode task (PA-12).
  • Task dengan penanggung jawab, tenggat, deskripsi, komentar, dan riwayat aktivitas.
  • Edit bersamaan saat offline digabung otomatis, dengan tanda "sudah digabung".
  • Halaman "Task saya" dari semua proyek.
  • Pengingat tenggat lewat notifikasi Windows.

Selesai kalau: dua orang mengubah task yang sama saat salah satunya offline, dan setelah tersambung keduanya melihat hasil gabungan yang sama tanpa data hilang.

Tahap 4. Dokumen dan edit file

2 sampai 3 minggu
  • Layar Dokumen per proyek dengan status setiap file.
  • Edit di Word atau Excel, tanda "Sedang diedit", dan versi baru otomatis setelah disimpan.
  • Riwayat versi yang bisa dipulihkan, dan penanganan bentrok dengan menyimpan kedua versi.
  • File besar diunduh saat diklik dari laptop mana pun yang punya salinannya.

Selesai kalau: file Excel yang diedit dan disimpan di satu laptop muncul sebagai versi baru di laptop rekan, dan versi lama bisa dipulihkan.

Tahap 5. Tanda tangan PDF

2 sampai 3 minggu
  • Penampil PDF di aplikasi, dengan komentar, stabilo, dan kotak teks.
  • Menggambar dan menyimpan tanda tangan, dilindungi PIN.
  • Permintaan tanda tangan dengan urutan yang ditentukan pengirim, termasuk Tamu kalau diminta.
  • File dikunci setelah ditandatangani, peringatan kalau isinya berubah, dan halaman catatan siapa serta kapan menandatangani.
  • Kartu task tanda tangan pindah ke Selesai otomatis.

Selesai kalau: kontrak ditandatangani berurutan oleh tiga orang, dan mengubah satu karakter di file hasilnya langsung memunculkan peringatan.

Tahap 6. Fitur lengkap

3 sampai 4 minggu
  • Board lengkap: prioritas, label, sub-task, estimasi, kolom tambahan, tampilan Daftar dan Kalender.
  • Chat lengkap: reaksi, edit dan hapus pesan, pencarian, ubah pesan jadi task, pin pesan.
  • Halaman Keamanan admin untuk perubahan yang ditolak.
  • Pengaturan status "Dibaca" per orang.

Selesai kalau: semua keputusan di dokumen brainstorming sudah ada di aplikasi, kecuali yang ditandai "Lanjutan".

Tahap 7. Uji coba kantor

1 sampai 2 minggu
  • Pilot dengan 3 sampai 5 orang selama sekitar satu minggu kerja.
  • Kunci cadangan superadmin di flashdisk, dan pengingat kalau superadmin baru satu.
  • Installer final dan panduan singkat untuk pengguna serta admin IT (VPN dan firewall).
  • Perbaikan dari masukan pilot.

Selesai kalau: tim pilot memakai Mira untuk pekerjaan nyata selama seminggu tanpa kehilangan data.

Setelah tahap 7

  • Fitur "Lanjutan": sprint, laporan, thread diskusi, indikator mengetik, panggilan suara di LAN.
  • Tema Kertas dan Panel.
  • Logo final.
  • Aplikasi HP lewat VPN kantor.

Cara menguji

  1. Tes otomatis untuk inti Rust, terutama penggabungan perubahan, titipan pesan, dan pemeriksaan izin, karena di sinilah kesalahan paling sulit dilihat.
  2. Beberapa "laptop" di satu komputer. Aplikasi bisa dijalankan beberapa kali dengan folder data berbeda, jadi skenario tiga orang bisa dites tanpa tiga laptop.
  3. Daftar skenario offline yang dijalankan di setiap tahap: laptop mati di tengah pengiriman, dua orang mengedit bersamaan, pengirim offline sebelum pesan sampai, jaringan putus saat file besar diunduh.
  4. Tes di jaringan kantor sungguhan dengan minimal tiga laptop, termasuk satu lewat VPN dari luar kantor.

Risiko dan cara mengatasinya

RisikoCara mengatasi
Router kantor memblokir penemuan otomatisInput alamat manual, QR code, dan alamat terakhir yang diingat sudah dibangun sejak tahap 1.
Penggabungan edit bersamaan lebih rumit dari perkiraanMemakai Automerge yang sudah matang, dan menguji dengan banyak skenario offline sejak tahap 3.
Word mengunci file saat dibuka dan membuat file sementaraMira hanya mengambil versi baru setelah file benar-benar disimpan dan ditutup, dan mengabaikan file sementara Office.
Disk laptop penuh karena fileBatas sekitar 20 MB untuk salinan otomatis, dan pengaturan untuk membersihkan salinan file lama.
Laptop admin hilangMinimal dua admin dan kunci cadangan di flashdisk.
Windows memperingatkan saat installer dijalankanInstaller tanpa sertifikat penandatanganan kode akan diperingatkan Windows SmartScreen. Bisa diterima untuk pilot, tapi untuk dipakai luas sebaiknya membeli sertifikat.
Update aplikasi tanpa serverInstaller baru dibagikan lewat folder bersama atau flashdisk. Opsi lanjutan: update dibagikan antar laptop dan ditandatangani kunci admin.

Yang dibutuhkan dari Anda

  1. Minimal tiga laptop Windows untuk tes di jaringan kantor, mulai tahap 1.
  2. Bantuan admin IT untuk memasang VPN di router kantor dan memeriksa apakah mDNS diblokir.
  3. Microsoft Office di laptop penguji untuk tahap 4.
  4. Keputusan soal sertifikat penandatanganan kode sebelum tahap 7.
  5. 3 sampai 5 orang untuk pilot di tahap 7.
  6. Logo final, kapan pun siap.
