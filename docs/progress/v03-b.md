## Keputusan

1. Folder tetap `src/screens/org/` (kontrak menyebut `src/screens/organization/`), supaya impor di `Shell.tsx` dan riwayat file tidak berubah.
2. Peran ditampilkan sebagai gabungan: "Superadmin", "Superadmin, admin departemen", "Admin departemen", "Anggota", "Tamu". Dialog Ubah peran punya dua bagian terpisah: peran di departemen (radio, hanya kalau orang itu punya departemen) dan superadmin (centang). Langkah dijalankan berurutan, yang kedua tidak jalan kalau yang pertama gagal.
3. "Tolak semua dari alamat ini" berjalan di tampilan dengan `rejectJoin` satu per satu (tanpa command baru). Pengelompokan alamat sama dengan `ip_group` di Rust: satu IPv4 atau satu IPv6 /64. `join_already_decided` dilewati dan dihitung terpisah.
4. Hapus label = arsipkan, karena kontrak menyimpan pasangan lama. Istilah di layar "Hapus", "Dihapus", "Pulihkan" (mengikuti tombol Hapus di mockup).
5. Dialog yang punya isian atau konfirmasi menampilkan error di dalam dialog dan baru menutup kalau berhasil; aksi tanpa dialog memakai wilayah aria-live di atas tab. Wilayah itu tetap ada di pohon aksesibilitas saat kosong supaya pesan baru dibacakan.
6. Setelah aksi yang menghilangkan tombolnya (arsipkan, hapus, keluarkan, setujui, tolak), fokus pindah ke elemen berikutnya atau ke judul tab, tidak hilang ke body.
7. Laptop sendiri dihitung online untuk saringan; statusnya ditulis "Laptop ini" dan IP-nya "Tidak dicatat" (IP hanya dilihat dari koneksi rekan).
8. Pesan Rust yang masih menyebut "tim" (`invalid_name` untuk nama departemen, beberapa pesan kode undangan) ditulis ulang di tampilan dengan "departemen" (`\btim\b`). Teks aslinya ada di `permissions/`, yang bukan milik B.
9. Notifikasi OS dibuat di Rust (`org_screen.rs`) karena plugin notifikasi hanya ada di sisi Rust; event `mira://join-requests` dipancarkan agen A.
10. Desain: ikut arah tema Bata yang sudah ada (token di `src/theme/tokens.ts`, mockup yang disetujui), dial ENERGY 1 / RHYTHM 1 / MOTION 1 untuk halaman admin. Aksen hanya di tab aktif, tombol utama, angka menunggu, dan label.

## Catatan penggabungan

File di luar folder B yang diubah:
- `src-tauri/src/lib.rs`: `pub mod org_screen;`, `org_screen::spawn_join_notifier(app.handle());` sesudah `app.manage(state)`, dan `org_screen::org_fingerprint` di `generate_handler!`.
- `src/screens/shell/Shell.tsx`: satu impor dan `{id === "org" && <OrgNavCount />}` di tombol menu. D juga menambah angka di file ini; gabungkan kedua baris.
- `src/api/types.ts` (label peran), `src/api/messages.ts` ("admin tim" menjadi "admin departemen"), `src/styles/global.css` (`.dlg-title { overflow-wrap: anywhere }`, `.dlg-desc p + p { margin-top: 8px }`).
- File baru di luar folder: `src/api/orgScreen.ts`, `src-tauri/src/org_screen.rs`, `src/components/NameWithLabels.*`, `src/components/PeoplePicker.*`, `src/test/orgFixtures.ts`, `scripts/org-e2e.mjs`.
- Tidak menyentuh `permissions/`, `org_commands.rs`, `src/api/org.ts`, `network/`, chat, board, dokumen, onboarding. Tidak ada migrasi baru. Tidak ada command baru di `org_commands.rs`.

Untuk agen lain atau sesi utama:
1. **Profil laptop sendiri baru terbit saat start** (`ensure_device_op` di `lib.rs`). Setelah `create_organization` atau bergabung, baris laptop sendiri di tab Pengguna menulis "Belum dilaporkan" sampai Mira dibuka ulang (e2e harus membuka ulang laptop B). Usulan: panggil `permissions::ensure_device_op(..., &device::current(), ...)` sesudah `create_organization` (`commands.rs`), sesudah `join_with_code`, dan sesudah `install_approved_org` (alur A).
2. **Teks Rust masih "tim"**: `validate_team_name` di `src-tauri/src/permissions/format.rs` ("Nama tim ...") dan beberapa pesan di `permissions/actions.rs` (misalnya "Tamu tidak bisa memakai kode undangan sendiri. Minta admin tim memasukkan Anda."). Tampilan B sudah menggantinya, tapi sumbernya sebaiknya diperbaiki pemilik `permissions/`.
3. **Notifikasi** bergantung pada A memancarkan `mira://join-requests` (`org_commands::EVENT_JOIN_REQUESTS`) setiap kali permintaan masuk atau diteruskan. Tanpa event itu angka menu tetap benar (polling 30 detik), hanya notifikasi OS yang tidak muncul.
4. D bisa memakai `PeoplePicker` dan `NameWithLabels` alih-alih membuat komponen sendiri; C memakai `NameWithLabels` dengan `PersonView.labels` dari `orgApi.people()`.
5. Vitest di worktree: dua file gagal dimuat karena `node_modules` di folder induk (lihat tabel uji). Build release di worktree juga butuh `node_modules\pdfjs-dist` di worktree (`vite.config.ts` membaca `./node_modules/pdfjs-dist/cmaps`); agen e2e memakai junction sementara lalu menghapusnya.
